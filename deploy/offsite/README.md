# Private off-site storage preparation

These examples prepare the encrypted-backup boundary. They contain placeholders, no credentials, and no command that creates a bucket or applies a policy. Live application needs society-owned accounts, accepted custody/retention/cost policy, deployed-host checks and an independent restore. Current local evidence uses numeric-loopback fixtures.

The running service holds two distinct public age recipients and a scoped create-only writer credential. Each independently held private age identity can decrypt a copy; this is independent recovery with either custodian, not a two-person cryptographic quorum. The writer cannot retrieve or delete historical versions. A separate reader can retrieve an explicitly supplied version for the offline custody command.

## Configuration and authority

Copy `writer-config.json.example` to an operator-owned private location outside Git, replace every placeholder and restrict it to mode 0600. Remove `session_token` when using credentials without one. The canonical regional S3 HTTPS endpoint is derived from bucket and region; no arbitrary live endpoint is accepted. Supply an absolute `--offsite-config-file` to the paired service. Generate each custody identity separately with `society-server offsite-keygen --out NEW_PRIVATE_FILE`; it prints only the public recipient. Keep identities away from the running host and backup bucket, alongside the separately recoverable MFA/message encryption keys.

Adapt the writer and custodian identity policies to separately controlled principals and the same destination prefix. Bucket controls additionally require conditional creation and deny the runtime writer read/deletion/administration. These are policy drafts to validate against actual account policies, role boundaries and the service API. An attachment alone does not prove effective live permissions. Require `If-None-Match: *`, a correct SHA-256 acknowledgement and a non-null version; a conflict or lost reply remains uncertain. [AWS conditional-write policy documentation](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes-enforce.html).

`bucket-settings.json.example` groups three API payloads; it is not a single AWS CLI request. Verify versioning, public-access blocking and ownership on the actual bucket. After first enabling versioning, AWS documents a propagation wait before writes. The application rejects an unversioned acknowledgement. [AWS versioning setup](https://docs.aws.amazon.com/AmazonS3/latest/userguide/manage-versioning-examples.html).

A non-fictional `LOCAL_WORKSPACE` pauses financial effects even before configuration and rejects fixture storage as protection. Only explicitly synthetic development can operate unprotected. The first configured destination/public-recipient binding is retained in SQLite. Credential rotation preserves that binding; changing destination or recipients needs a separate migration/recovery decision. Restarting a bound database without its configuration fails. The serving command refuses private custody identities. The portal and native WebMCP expose status only, without upload/configuration/reconciliation/override controls.

## Schedule, limits and retention

The scheduler reserves a new capture every 30 minutes, serializes competing workers and retains at most four unconfirmed encrypted copies. Each job has at most five attempts. Explicit rejections retry the same encrypted bytes and identity; ambiguous handoffs are retained for independent investigation. A crash after acknowledgement is cleaned up on the next worker start without deleting unknown or unconfirmed originals. Physical limits are 256 MiB per encrypted copy, 512 MiB per raw snapshot, and 64 staged files within a bounded aggregate. Larger real data requires a reviewed limit/storage change.

Freshness begins before capture, not at a delayed upload acknowledgement. Missing usable protection pauses new financial effects; warning begins at 45 minutes and the default pause at 60 minutes. Reads, drafts, security revocation and saved replies continue. Clock inconsistencies also pause effects. There is no committee override without an accepted policy.

The lifecycle draft follows the plan's proposed retention classes and leaves every rule disabled. This checkpoint's scheduler writes routine copies to its bound prefix. Daily/monthly/release-class capture and release-triggered off-site checkpoints remain subsequent operations work; the extra draft prefixes do not establish those copies. A 366-day monthly proposal conservatively covers twelve calendar months. Current-version expiry and noncurrent-version cleanup are separate, so the seven-day noncurrent grace can add to billed retention. Preserve any incident hold before enabling cleanup; independently forecast all versions, requests and transfer. [AWS lifecycle examples](https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-configuration-examples.html).

Versioning and limited runtime authority do not independently protect against privileged account compromise. Offline verified copies, separate custody, control of deletion/lifecycle authority and the actual retention decision remain required.

## Independent recovery and acceptance

For an uncertain handoff, the custodian uses a private reader configuration with the same destination/public recipients, a private identity, the retained job ID and independently obtained exact version in `offsite-reconcile`. It retrieves, checks the encrypted checksum, decrypts and verifies the archive before recording reconciliation. A late acknowledgement preserves the old capture age. `offsite-decrypt` also accepts an independently supplied checksum and extracts into a new private directory. Run `restore-check` with the matching release into a fresh database, verify current account access and representative financial originals, then follow the [restore-reconciliation contract](../../docs/restore-reconciliation-workflow.md). A restored capture journal cannot authorize replay of an old external handoff.

Activation evidence must show writer upload succeeds but reader/delete/control requests are denied; custodian exact-version retrieval/decrypt/restore succeeds but writes are denied; lost replies remain uncertain; current originals, corrections, keys and denied old bearers survive a replacement-host restore. Verify clock behavior, reboot recovery, alerting and HTTPS on the actual host. Local protocol tests and JSON parsing do not establish live IAM, retention, availability or production acceptance.
