## Implemented workflow and authority

CLI bootstrap requires explicit database, private bounded setup/password files and separate key destinations. It refuses occupied data before migration or key creation. A new configured workspace has one verified, non-demo registry administrator, mandatory real MFA and no inferred finance appointment. Exact setup/password/key retry preserves the existing account, later password/MFA changes and key bindings. A missing or replacement bound key fails safely. `serve --workspace` uses the explicit local database and keys; it never seeds demo accounts. Public configuration returns only the workspace name and mode, and sign-in waits for that verified configuration before presenting the appropriate controls.

The Initial register form is available only to current registry administrators. JSON is bounded to 2 MiB and strict UTF-8/versioned fields; duplicate keys/identities, missing references, invalid dates, overlapping relationships and inconsistent occupancy fail with bounded row errors. Preview is read-only and binds the exact supplied file, current registry digest and effective date. The operator reviews totals, searches homes, opens their proposed relationships and supplies a verification note before confirmation. A stale register or revoked authority commits nothing. Confirmation inserts all entities, source provenance and audit in one transaction; identical acknowledged retry returns the retained result, while changed retry details conflict. A lost response causes no automatic write replay.

Import creates no accounts, finance visibility, inferred charges or balances. The independently supplied [fictional register](../testdata/registry-import-118.json) gives **118 homes: 109 occupied, 9 vacant, 74 owner occupied and 35 rented; 118 distinct current owners and 35 tenants; 154 people and 155 relationship rows**, retaining joint/multiple-home ownership and a former tenant. The same-source result remains immutable after reviewed registry edits. Normal invitation/activation proves that a current A-103 tenant sees only current members in that household, with no initial-import or finance authority.

Actual native Chrome exposes only bounded current import counts/status. Source identifiers, file digests, names, notes and credentials stay out of that tool. Navigation to the form respects active human input; there are no bootstrap, preview or apply mutation tools. Current revocation discards held native results and removes discovery.
