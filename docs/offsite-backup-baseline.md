## Verified outcome

A configured scheduler captures a consistent SQLite snapshot every 30 minutes and encrypts a bounded archive to two or more independent age recipients. The running writer receives public recipient material. Signed create-only upload requires the original SHA-256 checksum and a non-null object version. A lost reply, conflict or unverifiable success stays uncertain and is not automatically sent again. An independent custodian retrieves the exact version, decrypts and verifies it before reconciliation. Freshness remains tied to the original capture time.

Required protection warns at 45 minutes and pauses new financial effects at 60 minutes. Database triggers cover the [enumerated confirmed money, counter, allocation and composite transitions](offsite-backup-workflow.md#implementation-decisions-after-household-publication). Drafts, appropriate reads, security revocation and exact previously accepted acknowledgements remain available. Original entries, receipts and audit are preserved with linked corrections. Clock rollback or a future recovery point pauses new effects.

An unconfigured non-fictional workspace is already paused. Numeric-loopback fixture storage cannot bind protection for `LOCAL_WORKSPACE`; only explicitly synthetic development may continue without configured off-site protection. This implements the default guard without inventing an adopted committee override policy. The retained fictional preview is explicitly unprotected.

The approved operator screen exposes protection, capture age and retained attempts. Filters and event pages are bounded to twelve records. Real controls support keyboard selection, Escape, focus restoration and internally scrolling history with a fixed close control. Residents cannot discover or read global recovery history. Native WebMCP exposes bounded current reads and no upload, configuration, financial confirmation or override.
