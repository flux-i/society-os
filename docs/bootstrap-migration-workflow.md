## User outcome and permissions

Prepare an empty society workspace without the public demo accounts or fictional sign-in shortcuts. A locally authorized custodian establishes the society and first registry administrator once, then completes the existing mandatory privileged MFA flow. Registry administration grants no finance appointment. Keep initial credentials and keys outside Git and ordinary logs; do not print usable passwords or tokens in reports.

The registry officer can validate a supplied register, review its exact proposed changes and deliberately apply an accepted import. No import infers financial balances, payment confirmations, consent, channel registrations or receipt numbers. Subsequent account invitations, reviewed changes and financial records keep their existing separate workflows and permissions. Native WebMCP may read permitted migration metadata or open its visible screen; it cannot bootstrap, import, approve or activate an account.

## Import and retry contract

Define a small versioned, documented input format for society/building/home/person/relationship data. Preserve supplied stable source identities, dates and occupancy; do not merge people by name or invent missing relationships. Validate bounds, required fields, dates, allowed relationship/status values, duplicate source identities, missing references and inconsistent active relationships before any mutation. Report row-specific actionable errors without echoing unnecessary private fields. An invalid import leaves all business rows unchanged.

Validation produces a bounded preview with counts, warnings and a digest of the exact supplied input. Applying requires current registry authority and deliberate confirmation of that exact preview. Concurrent registry changes invalidate a stale proposal. Transactional import preserves source provenance and immutable audit. Repeating an accepted operation with the same identity returns the same outcome; changing its input under that identity fails. Re-importing the same source must not duplicate homes or people or silently overwrite reviewed registry changes.

Refuse demo seeding into a non-demo workspace, non-demo bootstrapping over existing business data, accidental replacement of existing keys and unacknowledged destructive imports. Keep the existing developer preview and all accepted archives untouched. New setup and import commands must make their local destination explicit and remain safe to retry after interruption.
