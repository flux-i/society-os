# Foundation decisions · 4 October 2026

The application is one Go process with explicit SQL and a same-origin React/Vite frontend. Built assets ship beside the binary in `build/web`; Node is needed for building, not for serving. No application LLM, payment gateway, bank integration or Tally runtime dependency is introduced.

SQLite uses pinned `modernc.org/sqlite` v1.60.1. Its pure-Go build avoids a C toolchain for the selected Linux targets. The actual embedded engine is measured in the CLI/API and baseline rather than inferred from a system SQLite installation. The driver brings its pinned `modernc.org/libc` dependency through its module graph. [Driver documentation](https://pkg.go.dev/modernc.org/sqlite).

Every connection receives WAL, FULL synchronization, foreign keys and a 5-second busy timeout through the driver's DSN parameters. The pool is limited to four connections. Startup rejects engines without a documented WAL-reset fix and mismatched settings. Tests reserve four simultaneous connections to verify setup. [SQLite WAL documentation](https://sqlite.org/wal.html).

Migrations ship in the Go binary, run transactionally and retain SHA-256 provenance. Schema 4 adds immutable posted manual records, linked corrections, operation identities and leased private receipt PDFs. The registry uses unique flat identities, explicit resident relationships, membership intervals and separate finance-access flags, without treating a contact as an authenticated identity.

Schema 5 adds separate-reviewer proposals and atomically published audience-scoped notices. Schema 6 adds personal service requests and immutable public/private updates. Resident case versions and timestamps advance only on public updates; handler metadata retains the full history. Current author membership governs participation, while ended authors retain only their own read-only case history. Handler permission and assignment eligibility are separate from financial posting.

Schema 7 adds immutable original-document metadata/bytes, scoped collections/versions, actor-bound upload and decision retries, separate approval, quotas and leased content checks. The synthetic local adapter stores bounded originals in SQLite so consistent snapshots recover them with the review state. This is a deliberate local development choice, not an implemented production S3 adapter. Moving originals to S3 must preserve checksum/version, validation, current audience, archive and recovery contracts. Financial document permission stays separate from registry administration. See [document acceptance](documents-baseline.md).

Schema 12 adds independently published supplied rules, private incident reports, immutable decoded picture originals and metadata-free previews, scoped access audits and deliberately issued frozen household notices. Reporter, handler and subject reads have distinct histories and visible versions; private notes do not advance household/reporter state. Current authority, fresh authentication, versions and actor operation identity are rechecked within writer transactions. Reports, substantiation and responses create no financial entry. The six native tools expose metadata only. Conduct dialogs reserve a non-scrolling close-control row so captions and scrolled content stay clear at narrow widths. See [incident acceptance](incidents-baseline.md); [separate fines](fines-workflow.md) are the next financial workflow.

PDF-original checks use installed qpdf 12.4.2 in a bounded subprocess, inspecting canonical structural dictionaries without embedding/rendering the original or invoking OCR. Actual image decoding rejects damaged/wrong-type/oversized-pixel images. Missing PDF checks fail closed and permit explicit retry. This adds a documented host executable dependency alongside the Go binary; it does not establish antivirus or hard memory containment. Production S3/scan isolation and target-host operation remain acceptance work.

A continuing preview runs a retained, matching binary and frontend under a private checkpoint directory. `scripts/pin-preview.py` packages an already verified build without data or keys; rebuilding the next milestone cannot replace the live preview's assets. The database still migrates only when the new retained release is explicitly started. Keep the pre-upgrade snapshot and matching release for recovery.

The server remains a local synthetic preview. It requires the fixture marker and demo flag and rejects non-loopback binds and untrusted Host values. Schema 2 added password sessions, time-bounded roles, scopes, registry mutations and immutable audit. Schema 3 adds invitation/assisted recovery, privileged TOTP, hashed recovery codes and fresh checks. Schema 8 implements explicit account administration locally; real identity/custody and production authority acceptance remain separate gates.

Passwords use pinned `golang.org/x/crypto` v0.57.0 Argon2id with 64 MiB, three passes and two lanes; calibrate against production hardware before deployment. The HTTP layer permits at most two simultaneous password checks and bounds/throttles login attempts. Session tokens have 256 random bits and are stored by SHA-256 hash; CSRF tokens are separate random values. Cookies are HttpOnly/SameSite Strict. Secure cookies apply under TLS; the current CLI permits only loopback HTTP. [Go Argon2 documentation](https://pkg.go.dev/golang.org/x/crypto/argon2), [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Sessions have 30-minute idle and 8-hour absolute limits. Background identity checks do not extend idle lifetime. Role expiry/revocation, account/auth-version changes and current membership scope are rechecked per request. Origin and synchronizer-token checks protect writes. Registry edits reserve the SQLite writer before permission reads, compare the home version and commit the mutation/audit atomically. A rejected edit leaves no record, version or audit side effect. [OWASP sessions](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [OWASP CSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

The demo administrator manages registry/accounts, while committee/treasurer grants provide operational registry reads. Administrators can invite current registry people and issue reset links after fresh verification. Residents receive only active homes and current people; staff may inspect history. Finance reads use explicit membership entitlements or current committee/treasurer/auditor grants; registry administration alone cannot read all finance or post. Auditors retain financial reads without broad registry or writes. The fictional officer has an explicit additional treasury grant. See [manual-record acceptance](manual-records-baseline.md) and [account acceptance](account-administration-baseline.md).

The local recovery command uses `VACUUM INTO`, removes sessions, access links and recovery codes from the private copy, validates integrity/foreign keys/migration provenance and writes a versioned manifest. Restore requires a fresh destination and verifies copied bytes and counts. Identity/audit and confirmed encrypted factors survive; temporary credentials cannot revive. Preserve the matching MFA key separately. Encryption, S3 snapshots, recovery keys, current-access reconciliation, external effects/numbering and custodian-held recovery remain separate production requirements.

Frontend dependencies are exact versions with a lockfile. Tailwind's build-time styling and locally packaged fonts provide the visual foundation. The PWA manifest defines the app shell identity; no service worker stores personal API responses. [Vite documentation](https://vite.dev/guide/).

MFA uses RFC 6238 TOTP, consumed-step replay protection and a persistent five-attempt/15-minute budget. AES-256-GCM binds encrypted factors to their user. The private key is outside snapshots; missing/wrong keys fail startup/readiness. Browser-generated QR codes remain local. Password reset preserves factors and revokes sessions. Lost-factor recovery is an offline two-custodian attestation command, with no web disable/reset endpoint. [Account-security acceptance and boundaries](account-security-baseline.md).

Invitation/reset links are random, hashed, expiring, single-use and authentication-version-bound. Manual identity/email attestation precedes issuance and handover. Admin/committee roles have bounded terms. Sensitive actions require confirmation within five minutes. The four public demo accounts alone have a synthetic MFA exploration helper; invited accounts do not. Production use stays disabled.

The changing overview adds five independently retriable read snapshots under `/api/overview/{section}` without a schema migration. Current principal/scope checks precede each aggregate and bounded metadata preview. Financial credits and positive balances are computed per home; all daily windows use existing Asia/Kolkata dates. No overview mutation or provider/runtime AI dependency is added. See [overview acceptance](overview-baseline.md).

Schema 8 preserves previous identities, grants and audit while adding an access version, explicit suspension and Auditor appointments. Current administrator authority, freshness, expected version, successor check and immutable decision audit share the writer transaction. Grant/end invalidates recipient sessions/links; suspension also ends appointments/codes. Resume never restores old authority or credentials. A stable opaque fingerprint of current roles/active memberships is computed in the principal read snapshot. The frontend uses it to discard formerly authorised data, and native tools compare current scope before/after reads; it never serves as an authorisation credential. Ordinary unchanged identity refreshes preserve forms. Natural term/membership expiry changes scope without requiring a mutation counter. See the account baseline's reproduced expiry and in-flight membership failures.

## 5 October 2026 — one ledger for maintenance and reusable allocations

Release 0.10/schema 9 publishes manually supplied, separately reviewed maintenance charges into the existing immutable ledger. Frozen proposal/participant/history tables retain the approval source; publication issues no receipt. Generic same-home allocation links connect unreversed received/opening credit to unreversed charges/opening debit without creating or renumbering a receipt. Linked corrections and entry reversals retain history while derived live links stop affecting balances. Writer reservation, actor-bound exact-payload retries, current Treasury/factor authority and SQL guards prevent duplicate publication, credit overspending or charge overfilling. Read transactions apply current home/financial scope before deriving counts/amounts and bounded pages. See [maintenance acceptance](maintenance-baseline.md); upkeep remains a separate operational checkpoint.

## 5 October 2026 — private upkeep and frozen resident updates

Release 0.11/schema 10 uses current Administrator/Committee operational authority separately from Treasury. Immutable register/work events retain supplied dates, assignments, retirement, repeat sources and different-actor completion checks. Explicit publication has its own frozen resident title/body/state/dates/version; private activity never leaks its version, timestamps, search or counts. Resident structures are rebuilt from that snapshot and current home/wing scope. Current-scope changes clear queried detail links before mounting the replacement workspace, and native responses recheck scope before returning. Bounded read-only tools omit private register/body/contact/activity fields. See [upkeep acceptance](upkeep-baseline.md).

## 5 October 2026 — verified external money and one original receipt

Release 0.12/schema 11 freezes fixed or voluntary fund proposals and their participants before different-Treasurer publication. Fixed funds reuse the existing charge ledger; voluntary funds create no debt. Residents' paid reports retain revisions and private evidence. Different-actor confirmation uses a unique normalized external source/payment identity to create or link one original received entry and its receipt through the shared issuer. Compatible previously posted manual money must be linked; duplicate reports never add cash, receipts or allocations.

Live credit combines maintenance allocations and voluntary contributions under one same-home cap in Go and SQL. Gross received money stays unchanged; attributed voluntary contributions are unavailable for paying debt. Reversals retain history without moving allocations automatically. A separately approved waiver retains its source, expected version and decision, reverses/replaces the original charge, and releases its old links without altering receipts. Current authority, confirmed factors and home scope precede retry replay and reads. Bounded native tools omit payment identities, private comments, evidence and decision reasons and expose no writes. Collections become the eighth independently retriable overview source. See [collections acceptance](collections-baseline.md).

Browser suite arguments now use escaped file names with both a path boundary and an end anchor. The previous suffix match allowed a populated collections fixture into an overview suite that expected an empty database. Each suite retains its separate synthetic database; production throttles and meaningful expectations are unchanged. Screenshot manifests bind the inspected captures to the final successful run, dimensions and hashes.
